# 🤖 Рекомендації та контекст для AI Асистентів (AGENTS.md)

Цей документ створений спеціально для LLM та AI-асистентів (GitHub Copilot, Cursor, Antigravity та інших), які працюють з кодовою базою проєкту `generator_bot`. Він містить ключові правила, архітектурні рішення та контекст для написання якісного коду.

## 🎯 Суть проєкту
Система управління генераторами (основний та аварійний), яка складається з Telegram-бота та веб-інтерфейсу (Mini App). Виконує облік палива, запис на зміни, розрахунок мотогодин, технічного обслуговування та двонаправлену синхронізацію з Google Sheets.

## 🛠 Технологічний стек
* **Мова:** Python 3.10+
* **Бот-фреймворк:** Aiogram 3.x
* **Веб-сервер:** `aiohttp` (асинхронний REST API для Mini App)
* **Frontend:** Vanilla HTML/CSS/JS (знаходиться в теці `webapp/`)
* **База даних:** Підтримується як SQLite (для розробки), так і PostgreSQL (за допомогою `psycopg[binary]` та `psycopg_pool`) для production.
* **Синхронізація:** `gspread` для обміну даними з Google Sheets.

## 📐 Архітектурні принципи та правила для AI

### 1. Робота з базою даних
* **Дві СУБД:** Всі SQL-запити та моделі в абстракціях бази даних (тека `database/`) повинні бути сумісними як з SQLite, так і з PostgreSQL. 
* **Журнал (Logs):** Усі події (заправка, старт/стоп генератора, ТО) генерують унікальні записи в журналі локальної БД. Не записуйте ці події напряму в Google Sheets. Поточний стан (наприклад, `current_fuel`) виступає кешем для UI.

### 2. Структура Telegram Mini App
* Інтерфейс (Mini App) обробляється всередині `webapp_server.py`. 
* Статика не використовує складних фреймворків типу React. Всі зміни в інтерфейсі (HTML/CSS/JS) в теці `webapp/` мають використовувати Vanilla JS без бібліотек, якщо немає іншої вказівки.
* Всі API ендпоінти для Mini App повинні бути асинхронними та оброблятись в середовищі `aiohttp`.

### 3. Telegram-Бот (Aiogram 3)
* UI для користувачів в Telegram бота використовує парадигму **Single-Window UI**. Бот намагається тримати всі взаємодії в одному повідомленні (оновлюючи його).
* Дані в бот проходять валідацію. Обробники (handlers) розмежовані на адміністраторські та загальні.

### 4. Робота з Google Sheets
* Двонаправлена синхронізація використовує алгоритм вирішення конфліктів. Не змінюйте логіку експорту/імпорту без явного дозволу, оскільки від цього залежить цілісність даних.
* Взаємодія з Sheets відбувається асинхронно і не повинна блокувати головний Event Loop бота.

### 5. Обробка часу та таймзон
* Проєкт використовує часовий пояс `Europe/Kyiv`. Усі розрахунки змін та годин роботи (комендантська година, тощо) залежать від налаштувань `WORK_START` та `WORK_END` у `.env`. Завжди враховуйте таймзону при збереженні об'єктів `datetime`.

## 📌 Як додавати нові фічі
1. Проаналізуйте існуючі сервіси в папці `services/`.
2. Якщо фіча впливає на дані, створіть зміну в схемі БД (адаптувавши і під SQLite, і під PostgreSQL).
3. Додайте обробник API у веб-сервері, якщо фіча має бути доступна в Mini App.
4. За необхідності, додайте кнопку або команду в `handlers/` Telegram-бота.
