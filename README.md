# ⚡ generator_bot

Telegram-бот для ведення роботи генератора: зміни, паливо, технічне обслуговування, графіки відключень та розумна двонаправлена синхронізація з Google Sheets.

---

## ✨ Можливості

### 🕒 Управління змінами
- **Послідовні зміни**: `m` (ранок), `d` (день), `e` (вечір) + `x` (екстра без черги)
- **Старт/Стоп**: логування подій з прив'язкою до персоналу
- **Робочий час (комендантська година)**: заборона **СТАРТ** поза `WORK_START_TIME` - `WORK_END_TIME`
- **Авто-закриття**: зміна автоматично закривається о `WORK_END_TIME` + сповіщення адмінам
- **Нагадування**: за `STOP_REMINDER_MIN` хвилин до закінчення робочого дня

### ⛽ Облік палива
- **Витрати**: розрахунок витрат (`години × FUEL_RATE`)
- **Заправки**: з номером чека та водієм
- **Робочий час**: заборона **📥 ПРИЙОМ ПАЛИВА** поза `WORK_START_TIME` - `WORK_END_TIME`
- **Паливо на головній**: під час роботи генератора залишок може показуватись як **(оцінка)** — розрахунок «на льоту» від часу роботи та `FUEL_RATE`
- **Алерти**: сповіщення адмінам при паливі нижче `FUEL_ALERT_THRESHOLD`
- **Корекції**: ручна зміна залишку палива адміном (з логуванням)

### 🔧 Технічне обслуговування
- **Мотогодини**: автоматичний підрахунок та відображення
- **ТО мастила**: нагадування за `OIL_CHANGE_HOURS` годин
- **ТО свічок**: нагадування за `SPARK_CHANGE_HOURS` годин
- **Запис ТО**: логування заміни мастила/свічок з оператором

### 🧠 Розумна синхронізація з Google Sheets

**Нове в версії 2.1!** Двонаправлена синхронізація, яка замінила старі окремі імпорт/експорт:

#### ✅ Як працює:
- **Порівнює дані по датах** між БД та Sheets
- **Для кожної дати визначає**:
  - Якщо дата є **тільки в БД** → експорт в Sheets
  - Якщо дата є **тільки в Sheets** → імпорт в БД
  - Якщо дата є **в обох** → вирішує конфлікт (більше даних = пріоритет)
  - Якщо дані **однакові** → пропускає

#### ✅ Додаткові функції:
- **Перевірка витрат палива**: порівнює колонку U (л/год) з `config.FUEL_CONSUMPTION`
- **Синхронізація довідників**: двонаправлене оновлення водіїв (кол. R) та персоналу (кол. S)
- **Детальний звіт**: після синхронізації показує:
  - Кількість експортованих днів
  - Кількість імпортованих днів
  - Вирішені конфлікти
  - Попередження про незбіг витрат палива
  - Доданих водіїв та персонал
- **Логування**: кожна синхронізація логується в системний журнал бота (хто і коли виконав)

#### 🔒 Безпека:
- **Тільки для адміністраторів**
- **Можлива лише коли генератор вимкнено** (OFF)
- **Lock mechanism**: запобігає одночасним синхронізаціям
- **Безпечно**: не перезаписує дані, а саме синхронізує зміни

> 📌 **Примітка**: Старі модулі `sheets_import.py` та `sheets_export.py` залишені як резервні утиліти, але не доступні через інтерфейс бота.

### 📝 Системний журнал подій

Всі події бота (старт/стоп змін, заправки, ТО, корекції, синхронізації) логуються у **внутрішній БД бота**:
- `log_id` — унікальний ID події
- `timestamp` — час події
- `event_type` — тип події (m_start, m_end, refill, corr_fuel_set, sync, ...)
- `actor` — хто виконав (ПІБ або Telegram username)
- `value` — значення (літри/години або звіт синхронізації)
- `driver` — водій (для заправок)
- `receipt_number` — номер чека (для заправок)

**Доступ до журналу**: через бота (кнопка "🕘 Останні події") або адмін панель.

> ⚠️ **Важливо**: Журнал подій зберігається **тільки в БД бота**, Google Sheets НЕ містить вкладку з подіями.

## ⚙️ Налаштування

### 1) `.env`

Скопіюйте `.env.example` → `.env` і заповніть:

#### Обов'язкові параметри:
```env
BOT_TOKEN=your_telegram_bot_token
SHEET_ID_PROD=your_google_sheet_id_for_production
SHEET_ID_TEST=your_google_sheet_id_for_testing
ADMINS=123456789,987654321  # Telegram IDs через кому
```

#### Режим роботи:
```env
MODE=TEST  # або PROD (дефолт: TEST)
```

#### Sheets налаштування:
```env
SHEET_NAME=ЛЮТИЙ           # Назва основної вкладки
```

#### Часові налаштування:
```env
TIMEZONE=Europe/Kyiv
WORK_START_TIME=07:00      # Початок робочого дня
WORK_END_TIME=23:00        # Кінець робочого дня
BRIEF_TIME=08:30           # Час ранкового брифінгу
STOP_REMINDER_MIN=30       # За скільки хвилин до WORK_END нагадувати
```

> Поза `WORK_START_TIME–WORK_END_TIME` бот блокує **СТАРТ** та **ПРИЙОМ ПАЛИВА**.

#### Паливо:
```env
FUEL_RATE=0.8                  # Витрата л/год
# Також підтримується аліас: FUEL_CONSUMPTION=0.8
FUEL_ALERT_THRESHOLD=15.0      # Поріг для алертів (літри)
FUEL_ALERT_COOLDOWN_MIN=180    # Анти-спам алертів (хвилини)
```

#### Технічне обслуговування:
```env
OIL_CHANGE_HOURS=50.0      # Інтервал заміни мастила
SPARK_CHANGE_HOURS=100.0   # Інтервал заміни свічок
```

### 2) `service_account.json`

1. Створіть Service Account в [Google Cloud Console](https://console.cloud.google.com/)
2. Увімкніть Google Sheets API
3. Завантажте JSON ключ
4. Покладіть файл у корінь проєкту (поруч з `main.py`)
5. Надайте доступ до вашого Google Spreadsheet email-адресі з JSON файлу

### 3) Структура Google Sheet

#### Основна вкладка (напр. "ЛЮТИЙ"):
- **Колонка A**: містить рядок "сьогодні" (для пошуку поточної дати)
- **Колонки B-I**: часи змін (4 зміни × 2 колонки)
- **Колонка K**: залишок палива на ранок
- **Колонки N,P,Q**: привезено палива, номер чека, водій
- **Колонка R (28)**: список водіїв
- **Колонка S (29)**: список персоналу
- **Колонка U**: витрати палива л/год (для перевірки)

> ⚠️ **Важливо**: Вкладка "ПОДІЇ" більше НЕ використовується. Журнал подій зберігається тільки в БД бота.

## 🏗️ Архітектура

### Паливо: канон і відображення

- **Канонічний облік** — це журнал подій (`logs`) в БД бота. 
- `generator_state.current_fuel` використовується як **стан/кеш для UI** та офлайн-режимів.
- Під час `ON` на головній може показуватись **оцінка** залишку: `current_fuel - (час_роботи × FUEL_RATE)` (без списання в БД щохвилини).
